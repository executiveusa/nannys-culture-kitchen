# Communication Standard

**Make it easy to understand and easy to act on.**

1. **Start with the point.** Begin with the answer, the action, or what changed.
2. **Use plain words.** Explain like the reader is new to the subject, without talking down. Use an everyday example only when it helps.
3. **One idea at a time.** Use short numbered steps when sequence matters. End substantial work with one clear next move.
4. **Separate facts from plans.** Say what is proven, assumed, designed, implemented, tested, previewed, and production-verified. Show receipts.
5. **Show when seeing helps.** Use a browser page for side-by-side choices, diagrams, walkthroughs, motion sandboxes, design systems, or implementation plans. Keep a plain-text equivalent.
6. **Use motion when it teaches.** One idea per scene. Keep text readable. Caption meaningful video. No motion whose only job is to look busy.
7. **Think wide, then narrow.** Explore divergent options for hard choices, select one, and present the decision rather than dumping the brainstorm.
8. **No slop.** No jargon walls, fake proof, stock slogans, generic AI cadence, ornamental dashboards, or filler sections. A casual question gets a plain answer.
9. **End with the next move.** The reader should know what happens next without decoding the response.

## Agent application
- A2A packets use structured fields and acceptance tests, not motivational prose.
- Builder prompts define the intended result precisely. Do not tell builders to "make it premium" or "use your creativity" when a design decision should already be locked.
- When a design decision is consequential, record: DECISION / SOURCE / PURPOSE / WHY / REJECTED / BUILD RULE / PROOF.
